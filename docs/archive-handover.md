# 竣工资料组卷与移交

竣工验收前的组卷、移交、签收都在这个模块里。两个入口：

| 入口 | 路径 | 干什么 |
| --- | --- | --- |
| 竣工资料组卷 | `/archive` | 按单位工程建案卷、挂资料、登记缺页、多选卷册提交移交、存量迁移 |
| 移交签收 | `/archive/handover` | 建设单位逐卷核对、整组签收或整组退回、查看点名缺件 |

试验检测页（`/testing`）底部有"移交签收结论"面板：签收结论、缺报告案卷都能在那边查到。
**三处入口读的是同一份数据**（`archiveVolumes` / `archiveDocs` / `archiveHandovers`），结论不复制、
不另存，两边只认一份。

## 缺件口径：以资料清单为准

卷内实装与资料清单打架时，**以资料清单为准**。全系统只有一份缺件算法，在
`frontend/src/data/archive-rules.ts`：

- 清单按案卷类别（施工记录 / 试验报告 / 测量成果）列出必装清单项与要求份数；
- 卷内"已装卷"且对得上清单项的资料才计入实装，**待补页（缺页）的不算装齐**；
- 缺件数 = 未满足清单项数，缺件案卷点名到卷、到清单项。

算法带口径版本号（`RULES_VERSION`）。清单或算法调整后：

1. 升 `RULES_VERSION`；
2. 任何入口加载时会自动把存量移交记录按新口径重算一遍（只刷新缺件快照与口径版本，
   不动历史结论），组卷页也有"按清单口径重算"按钮可手动触发；
3. 每次落库前先把待签收移交记录的缺件快照按清单口径现算校验一遍，对不上就拒绝写入——
   保证组卷页和试验检测页读到的缺件数永远一致。

## 案卷状态机

```
组卷中 ──提交移交──> 待移交 ──整组签收──> 已签收
  ^                  │
  └──── 整组退回 ────┘
```

- 只有"组卷中"的卷能改构成（挂资料、撤资料、登记缺页、归类）；
- 缺件案卷不允许提交移交，提交时逐卷点名拦截；
- 签收时逐卷核对：任何一卷缺件就**整组退回**并在移交记录里点名到卷，整组回组卷中重报；
- **已签收是终态**：只能由资料员追加补充说明，任何入口都不能把结论改回待移交；
- 已退回的移交记录是历史，其中的卷补齐后可原组重报（首次提交时间不动）或换编组提交。

## 角色与权限

页面右上角切换角色（演示用）：

- **资料员**：建卷、改案卷构成、提交移交、存量迁移、给已签收卷写补充说明；
- **建设单位**：只能对待签收的移交组逐卷核对、签收或整组退回；签收后该账号对本组卷册
  即转只读，其他页面一律只读。

权限判断在 `frontend/src/api/archive-service.ts` 里逐操作校验，页面按钮只是顺手隐藏。

## 幂等、原子与核对

- **再递一遍仍按最早那次**：同一组卷册重复提交，直接返回最早的待签收记录，不重复登记；
  退回重报的保留首次提交时间，只刷新最近提交时间。
- **存不下就整体撤销**：所有改动先在内存草稿上算完，`saveAll` 一次落库；落库前校验
  （状态机、案卷↔移交记录一致性、缺件快照与清单口径一致）不过，或 localStorage 写不进去，
  整体撤销、缓存回滚，不留一半。
- **交完重新核对**：每次提交/签收后页面绕开缓存强制重读，中途断掉自动重试 3 次，
  仍失败就显示"核对失败，点击重试"——不拿内存里的老数据兜底。

## 存量工程迁移组卷

老模块（试验检测、轴线偏差、地表沉降、掘进环次、管片拼装、同步注浆）里的存量记录
没有单位工程字段，直接派卷会编造假数据，所以迁移分两步：

1. **存量迁移组卷**（组卷页按钮，资料员）：把老模块的记录逐条转成待认领资料
   （编号 `LS-<模块>-<id>`），挂到"待认领池"，不进任何正式案卷。重复执行安全，
   已迁移过的编号直接跳过。
2. **按单位工程归类挂卷**：资料员在待认领池里逐份选择目标案卷（组卷中的卷）和清单项，
   归到对应单位工程的案卷下；清单项必须与目标卷类别匹配。

## 缺页怎么补齐

1. 资料员在案卷详情里对缺页资料点"登记缺页"，写明页码范围，资料转"待补页"——
   该清单项按缺件计，案卷缺件数立刻体现，不能提交移交；
2. 补齐扫描件后点"补齐归档"，写明补齐情况，资料回"已装卷"，缺页说明里保留
   "原缺页 → 已补齐"的完整痕迹；
3. 若原件确实找不回，用"挂到案卷"补录替代资料（同清单项），并在已签收后
   用补充说明留痕。

## 实施顺序的权衡

先动数据层（统一缺件算法 + 原子存储 + 移交记录模型），再接组卷页和移交签收页两个入口，
最后把结论面板挂到试验检测页。这样从头到尾只有一份算法、一份数据，不存在"两边各写一份、
再对齐"的窗口期；试验检测页只读不写，放在最后接没有返工风险。
