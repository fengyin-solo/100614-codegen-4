# 盾构隧道掘进施工管理平台

面向盾构机台账、掘进环次、管片拼装、同步注浆、渣土外运、地表沉降监测与轴线纠偏的一体化盾构隧道施工管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `shield-tunnel-construction:entries` 这一项，或调用 `resetModule(模块)`。

## 竣工资料组卷与移交（`archive`）

按单位工程把施工记录、测量成果、试验报告组进案卷，再整批移交给建设单位核对签收。
数据单独存放在 localStorage 的 `shield-tunnel-construction:archive:v1`。

**状态机（单向）**：案卷只能 `组卷中 → 待移交 → 已签收`。多卷一次提交为一个移交批次；
建设单位逐卷核对后整组签收，任何一卷缺件则整组退回、卷册全部回到「组卷中」并点名到卷。
退回后按原卷册重报沿用最早批次号与首次提交时间（`submitNo` 递增）。已签收卷构成只读，
只能补说明，不能改回待移交。

**权限**：右上角切换账号。只有「资料员」能登记散件、挂/摘资料、补页、迁移与提交；
「建设单位」只能核对签收/退回并补说明。

**缺件口径（只维护一份算法）**：统一以《资料清单》条目为基准，见
`frontend/src/data/archive/algorithm.ts` 的 `computeVolumeMissing`：

1. 未挂件（含 v1 历史空挂占位）；
2. 试验报告未出具——以试验检测委托清单为唯一证据，委托不是「已出报告」即缺；
3. 页数不足——卷内实测页数（挂接修正值优先）少于清单要求页数。

资料清单与委托清单口径打架时**以资料清单为准**；委托清单只回答「报告出了没有」。
组卷页与试验检测页实时调用同一算法，落库前 `assertCrossEntryConsistency` 还会校验
两边缺件数与点名条目一致、连算两次结果确定，不一致就整笔撤销不写库。

**换版重算**：算法版本为 `ALGORITHM_VERSION`（当前 `v2-2026-10-05`）。首次载入若为旧版，
已生成移交记录会自动按新口径重算（结论不回退，只刷缺件快照并留痕）；也可在
「存量迁移与口径」页手工触发。

**存量迁移**：按单位工程一键建卷，散件按「工程+类别+清单名称」自动归卷；对不上清单的
散件进 `looseDocIds` 待人工认领；缺页/缺报告逐条给出补齐方式（试验报告只能回委托清单
出具后由系统同步入池，不许手工补）。

**可靠性**：写入走 `commitArchive`——内存改完整颗状态树后一次落库，写后读回校验，
失败重试一次；配额存不下直接整体撤销。所有读操作都现读 localStorage，不用内存旧数据兜底。

**端到端校验**：`node frontend/scripts/verify-archive.mjs`（esbuild 即时打包 TS），
覆盖权限闸口、缺件点名、整组退回、幂等重报、双入口一致、v1→v2 重算、存量迁移、
配额回滚等 15 组场景。
